# 评测决策规则（T8）—— 数据驱动的优化决策协议

依据：调研报告 §四 2.4（All-Pass@4 口径）+ 审查台账 E4（改进必须可归因）。
本文档是 fail_analyzer 输出的**人工拍板层**：机器给出建议，人按本规则裁决。

## 一、口径铁律

1. **主指标 = All-Pass@4**（同任务同 seed 的 4 次重复全过才算稳定通过）。
   pass@1 只作参考；两者背离 = 不稳定，禁止以 pass@1 宣布胜利。
2. **未校准任务（calibrated:false）的分数一律不计数**——只用于修 oracle。
3. 环境类失败（environment/timeout）>10% 先修机器，不进代码归因。

## 二、回滚/合入门槛

| 场景 | 判定 | 动作 |
|---|---|---|
| 改动后 All-Pass@4 下降 | 回归 | 回滚或补测后再合 |
| token 均值涨 >50% 且成功率不动 | "更贵但不更对" | 回滚候选（审查预设规则） |
| 新增任何 L1 门禁外失败/错误 | 回归 | 禁止合入 |
| 负向任务失败率上升（假 done/unverified_done↑） | 可靠性劣化 | 优先修复 0.7 gate |

## 三、优化项裁决（fail_analyzer 建议 → 拍板）

按缺陷票 `category` 分布裁决，**优先级 = 占比最大类别**：

1. **grounding** → 验证顺序：A3 语义过滤（词法 top-k）→ 0.1 投影 → 0.3 id×name
2. **perceptual** → A2 多窗口 → A3 按需下钻 → 0.8 actionability
3. **progress-perception** → P1-1.1 stall 账本（**若 loops 事件>0 但任务仍死 = "检测只说话不拔电"实锤，立即升最高优先**）
4. **recovery** → P1-1.2 proactive replan → P2-2.1 宏库
5. **environment** → 机器问题（锁屏/弹窗/网络），不改代码

裁决后动作：开 P0.5/P1 批次 → 实施 → 重跑同一任务集 → report 对比 →
**数字改善才允许合入，未改善的回滚**。

## 四、数据积累

- 每批评测结果（eval_results/*.jsonl）+ 缺陷票（defects.jsonl）随批入库，
  按 label 绑 git_sha 可回溯。
- 每周至少 1 批真实任务（B 端日常指令自动落 runs.jsonl），攒 20+ 行跑 report
  看真实分布，与评测台分布对照。

## 五、防自欺检查单（提交前过一遍）

- [ ] 这轮改动的对比批在同一台机器/同一任务集/同 seed 数？
- [ ] token 成本涨幅有数字？（不是"感觉没涨"）
- [ ] 负向任务的 unverified_done 没涨？
- [ ] 预存失败集合没有新增项？
